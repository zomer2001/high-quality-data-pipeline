# A 阶段基础链路完善记录

日期：2026-11-13

本轮已接通统一专题读取、采集与加工进度分离、候选入库规则检查、本体快照及网页依据展示。自动模型抽取保持关闭，当前图谱交互保留，实验数据继续独立。

## 已完成

1. **统一业务读取。** 网页专题规划和变化统计接入 ResearchDatabase 的已入库记录；保留专题资料归属、分类及排除设置。产品、技术、路线、参考项目使用业务库中的稳定 ID。旧专题表单适配只投影它支持的对象类型，其他类型仍在七维业务库和知识资产接口中；空白旧模板列不再生成新的采集缺口。
2. **分别记录采集与加工。** 新正文版本与知识变化分别计数。抽取关闭时，原文归档成功可以完成采集任务，显示“等待抽取”；连续无进展按新正文和知识变化共同判断。保留任务范围、联网开关、限时与任务上限。
3. **独立规则检查。** 新增 `searchos/knowledge_quality`，没有模型或搜索调用。引文绑定到正文版本和字符位置；重复引文保留多个位置；数值检查识别单一同单位数值明显不符的情况，Pint 支持可换算单位的等价检查。工况绑定、复杂语义和独立证据没有确证时显示待核。
4. **保守实体候选。** 在已有类型和命名空间约束下，用 RapidFuzz 补充相似名称候选；相似分数不触发自动合并，由现有预览确认路径选择已有对象或独立建档。
5. **版本与安全发布。** 当前字段目录仍是权威定义，预览产生字段、映射、关系及规则的内容哈希快照。快照和逐条检查通过参数化 SQL 随事实事务保存到现有元数据表；计划绑定规则版本，规则改变后拒绝旧计划。保留原有来源检查、整库指纹、签名计划、部分提交确认和幂等回执。
6. **网页接入。** 导入预览、字段数据库以及当前产品/技术详情的依据区域展示核验信息。历史记录标记为尚未按本版规则核验；新记录区分明确未通过和待核。原文、摘要继续分别保存。

## 当前能力边界

当前是基础规则检查和人工确认导入链路。引文存在、数值存在均不代表真实世界事实已经成立；当前模块不会把结构检查通过自动升级为语义确认。

来源独立性判断、四类冲突的完整路由、变更证据核验、自动修订与引用影响传播、定向补查和持久化 Agent 恢复属于后续 B 阶段。LinkML 正式维护入口、Docling 复杂表格定位以及动态本体提案管理属于后续扩展。本轮已安装并接入 RapidFuzz、Pint，未安装这些后续组件。

首版本体快照使用现有元数据表保存，未新增专用业务表。专题字段数量表示当前已入库字段，不代表所有可能字段已经填满。旧的展示层实体合并建议不再用于业务 ID，新增候选通过导入预览处理；可逆的业务实体归并历史仍需后续实现。
